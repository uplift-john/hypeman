1. [blocker] **The settings drawer moves focus every second during a live session and drops it on close.** The dialog's effect depends on `onClose`, which App passes as a new inline arrow on every render. The 1 s session tick re-renders App, so the effect cleans up and runs again each second. Each run sends focus to "Close settings", and `restoreTo` gets overwritten with an element inside the dialog. A keyboard or screen-reader user cannot work the drawer, and Escape leaves focus on `<body>`.
   - Evidence: a11y-r1 "drawer keeps focus where the user put it while the session ticks". After a 3 s tick, focus is on "Close settings"; after Escape it is on BODY. Source: src/App.tsx:181 and src/components/SettingsDrawer.tsx:34-64.
   - Fix: run the open/restore effect only on `[open]`. Keep `onClose` in a ref (`const closeRef = useRef(onClose); closeRef.current = onClose`), or pass a stable `useCallback` from App. Capture `restoreTo` only on the transition from closed to open.

2. [blocker] **The rate-limit countdown is announced every second.** `#hype-help` is `aria-live="polite"` and holds "…The next slot opens in 8:24." That text changes every tick for up to 10 minutes, so a screen reader reads it continuously.
   - Evidence: a11y-r1 "rate-limit countdown is not re-announced every second". 9 announcements in 10 s. Source: src/components/SessionView.tsx:187-189 and :90-93.
   - Fix: drop the live countdown from the live region. Announce a static sentence once ("Limit reached — next slot opens at 3:42 PM", wall-clock time) or leave out the countdown. Keep the ticking value in a non-live element (the button label or `#next-hype` is fine). Only put `feedback.text` in the live region.
