# Privacy & Security Review — iteration 1

VERDICT: PASS

None of the fail conditions apply:
- **API key is not reachable from the browser.** `npm run build` succeeds, and grepping `dist/` for `ANTHROPIC|sk-ant|apiKey|x-api-key|process.env` finds nothing. The Anthropic SDK is not in the client bundle. There are no `import.meta.env` or `VITE_` uses, and `.env` is git-ignored (only `.env.example` is tracked). Vite returns 403 for `/.env*` (its default `fs.deny`). The 502 auth error body names the env var but not its value. The log line is `[hype] upstream auth`; a fake key never appears in the server log (grep count 0).
- **Frames are sent only when it's about to comment.** `toDataURL` is called once, in `grabFrame` (src/capture/screenCapture.ts:88). Only `SessionEngine.generate()` calls it, after the rate-limit slot has been taken and only when `sendFrame` is true (`mode === 'real'`, App.tsx:76). Mock mode, or not knowing the mode yet, sends no pixels. Pausing and idle stop sampling, and the thumbnails used for idle detection stay in the browser. Nothing is written to disk, and request bodies are never logged (app.ts logs only the error kind).
- **Capture is clearly shown.** The header shows a pulsing "Sharing screen"/"Live" badge, which changes to "Share paused" when paused, and the status card shows Listening, Taking a look…, Paused, and so on. The browser's own sharing indicator also applies. Screenshots 03 to 09 confirm this.
- **The sensitive-content guard exists.** It works in three layers: a title regex before the model is called (app.ts:84 and mock.ts), model rule 5 plus rule 9 against prompt injection, and an output regex in `postFilter` (`lineLooksSensitive`).
- **`npm audit`: 0 vulnerabilities** in the full tree and in production dependencies. `npm test`: 129/129 pass.

Probes I ran on API port 8903 with web port 5303, using `ANTHROPIC_API_KEY=sk-ant-FAKEKEY…`:
- POST with `Origin: https://evil.example` → 403, both directly and through the Vite proxy (the Origin header is passed through).
- POST with `Origin: null` → 403. `Content-Type: text/plain` → 415, which blocks cross-site form posts and no-cors "simple" requests.
- Vite with `Host: evil.example:5303` → 403, so DNS rebinding of the dev server is blocked by Vite's allowedHosts check. Vite's CORS preflight for the evil origin returns no `Access-Control-Allow-Origin`.
- API with a rebound Host header → `GET /api/health` returns 200. It only exposes the mode and model name, and a rebound POST still sends a foreign Origin and gets 403.
- Window/tab title "Chase Bank - Statement" → `{"speak":false,"reason":"sensitive"}`, and the model is not called.
- The API binds to 127.0.0.1 only, and there is a server-side cost cap of 12 requests per 10 minutes in real mode.

ISSUES (ranked):
1. [major] The deterministic pre-send sensitive guard does almost nothing in Chromium, and the UI promise overstates it. The guard only sees `track.label`. In Chrome that label is opaque (`screen:0:0`, `window:…`, `web-contents-media-stream://…`), and `usefulHint()` discards those labels (shared/sensitive.ts:66-73), so `hint` is undefined. The label is also read only once at share start (screenCapture.ts:71) and goes stale with `surfaceSwitching: 'include'` or when the user switches tabs or windows inside a shared screen. In practice, a banking or password screen gets sent to Anthropic, and only the model instruction and the output filter keep it silent. The start screen still says "Banking, passwords, health and messages get silence." (StartScreen.tsx:77). Fix: reword the promise to something like "Hypeman is told to stay silent on banking, passwords, health and messages". Optionally, add a client-side check before `grabFrame` (skip capture when `isSensitiveHint(capture.hint)`), and document that title detection depends on the browser.
2. [minor] The UI never says that real mode sends frames to a third party. The start screen says "One screenshot is sent only when it's about to comment, then gone." (StartScreen.tsx:75) without naming Anthropic. Only the README discloses it (README.md:38). Fix: change the copy to "…sent to Anthropic's API only when it's about to comment; not stored by Hypeman", or add a "Real mode" badge with a tooltip saying where frames go.
3. [minor] When the window title is sensitive, the frame is still grabbed and POSTed to the local server before the server discards it. The hint check runs server-side (app.ts:84), but the frame was already encoded in engine.ts. It only crosses loopback, but it is a needless copy. Fix: in `SessionEngine.generate()`, return `silent('sensitive')` before calling `grabFrame()` when `isSensitiveHint(capture.hint)`.
4. [minor] localStorage keeps up to 100 generated lines (`hypeman.history.v1`, storage.ts:30/108). Those lines are meant to name specific on-screen things, such as file names, document titles and slide headings. The comment at storage.ts:5 says "never frames or screen text", which is inaccurate, and the "Nothing is stored" promise does not match. Fix: update the comment and copy ("Only Hypeman's own comments are kept, in this browser; clear them in Settings"), or lower the cap or add an expiry.
5. [minor] Notifications show the full line on the lock screen. `notify(line)` uses it as the body (notify.ts:24), and lines can name documents or projects. Fix: add a setting such as "Show comment text in notifications" (off means the body is "New hype — open Hypeman"). Alternatively, rely on the OS lock-screen redaction and mention it in the setting hint.
6. [minor] On narrow or scrolled viewports, the capture badge scrolls out of view. The header in SessionView.tsx:98 is not sticky, and the 360px screenshots 03/06 show the session with the header and Live badge off-screen. The status card and the browser indicator still show the state, so this is not a blocker. Fix: make the header `sticky top-0` with a background, or set `document.title` to "● Sharing — Hypeman" while `phase === 'active'` so the tab itself shows it.
7. [minor] Requests without an Origin header skip the allowlist (app.ts:62), so any local process can spend the key, within the cap of 12 per 10 minutes. This is acceptable for a local tool, but it could be hardened with a per-launch random token that the Vite proxy injects as a header, or by requiring `Sec-Fetch-Site: same-origin` when present. The 403 responses also lack `nosniff`/`no-store`, because the headers are set after `next()` and the early return skips them. That has no real impact.
8. [minor] Prompt injection from on-screen text: the defense is reasonable (rule 9, JSON schema output, post-filter, and React text rendering with no `dangerouslySetInnerHTML`). However, `normaliseReason` passes up to 60 characters of model-written `reason` to the client (real.ts:96). That text is never displayed except as `sensitive`, `nothing-notable` or `no-frame`, which are mapped. Fix (optional): map reasons to a fixed enum server-side so model text derived from the screen is never returned.
